# ANIXIA Product Scope v2

更新日: 2026-11-17

## 1. 基本方針

ANIXIAは、日本語・英語に対応するアニメ総合データベース／コミュニティサービスとして再設計する。

- ブランド表記は **ANIXIA** に統一する。
- 日本語を第一言語として設計し、英語表示にも対応する。
- キャッチコピーや広告的なヒーロー文言は設けない。
- 作品検索、作品詳細、ランキング、視聴ライブラリなど、利用目的が明確な通常のWebサイトとして設計する。
- MyAnimeListは情報設計・機能構成の参考とする。画面デザインや文章をそのまま複製しない。
- AQWで得た知見として、モバイル対応、読みやすさ、入力検証、データ重複防止、権限分離、サーバー側検証、変更単位のテストを採用する。

## 2. 作品収録条件は白紙から再定義する

旧プロジェクトで使用していた作品の収録・除外条件を、新ANIXIAの確定ルールとして引き継がない。

現時点では、以下をすべて**未決定**とする。データ取得や公開判定に、旧条件を暗黙に適用してはならない。

- 収録対象とする国・地域、制作体制、原作の範囲
- TVシリーズ、劇場作品、OVA、ONA、短編、特別編などの形式
- 総集編、再編集版、再放送、再上映、再配信の扱い
- リメイク、リブート、続編、スピンオフ、派生作品の作品単位
- 共同制作、海外制作、日本との共同制作の扱い
- ミュージックビデオ、CM、PV、教育映像などの扱い
- 成人向け・年齢制限のある作品の扱い
- 未放送・制作中止・配信限定などの状態
- 同一作品の別言語版、別題、重複レコードの統合方針

上記は、利用者が検索・整理したい範囲、データソースの正確性、権利条件、運用可能性を確認してから個別に決定する。

## 3. データ移行・既存DBの安全性

「白紙から再定義する」ことは、既存データやデータベースを無条件に削除することを意味しない。

- 既存Supabaseのテーブル、RLS、認証、ユーザーデータは、明示的な移行計画と検証なしに削除・変更しない。
- 旧収録条件で登録済みの作品を、自動で削除・公開・非公開にしない。
- 作品条件が確定するまでは、収録判定を保留できる設計を優先する。
- 外部データソースの利用規約、再配布条件、画像・文章の権利を作品条件と分けて確認する。
- service_roleキーなどの秘密情報をフロントエンドへ含めない。

## 4. 画面・情報設計

- ホーム：検索、主要ナビゲーション、人気作品、新着作品、ジャンル。
- 作品データベース：検索・絞り込み・並べ替え・ページ送り。
- 作品詳細：タイトル、別名、基本情報、あらすじ、関連作品、評価・レビュー。
- ランキング：ランキングの基準を明示し、異なる指標を混同しない。
- マイライブラリ：視聴状況、進捗、お気に入り、個人評価。
- 発見機能：おすすめ診断、ジャンル・季節別の探索。
- クイズ：出題品質、正答判定、回答履歴、スコアを検証する。
- アカウント：プロフィールとユーザー固有データを安全に管理する。

各機能の公開範囲と実装順は、画面・データ・権限の対応を確認してから決める。

## 5. 品質基準

- 日本語・英語の表示崩れ、未翻訳、誤訳を確認する。
- PC・タブレット・スマートフォンで横スクロールや操作不能がないこと。
- 読み込み中、データなし、通信失敗、認証失敗を区別して表示する。
- 空データや不正な入力でも画面が壊れないこと。
- ユーザー固有データはRLSで本人に限定する。
- クイズの正解や管理者専用処理を公開クライアントへ置かない。
- 変更ごとに対象ページの回帰テストを行い、GitHub Actionsの結果を確認する。
- 未検証の機能を完成扱いにしない。

## 6. 費用と技術

- GitHub Pagesと既存Supabaseの無料枠を前提に、月額0円を目標とする。
- 無料枠の上限、API制限、画像利用条件、運用負荷を確認する。
- 新しい外部サービスや有料APIを採用する場合は、採用前に費用と代替案を評価する。
