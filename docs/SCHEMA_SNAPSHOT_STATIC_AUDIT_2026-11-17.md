## 修正内容

- 初回の `05_grants.sql` にテーブル権限が含まれていなかったため、現行DBの権限カタログからテーブル権限を再取得して追加。
- 関数権限も現行カタログから再生成。
- 将来作成されるオブジェクトに適用されるスキーマ単位のデフォルト権限を `07_default_privileges.sql` として追加。
- READMEにファイル一覧と制約事項を追記。

## 静的検査で確認したこと

- 6つの主要SQLファイルのステートメント数が、README記載のオブジェクト数と整合。
- 47テーブルすべてにRLS有効化文が存在。
- 69個のポリシー定義を検出。
- インデックス名の重複は検出されなかった。
- 関数定義20件、トリガー定義11件を検出。
- GRANT文はテーブル・関数・デフォルト権限に分けて収録。

## 未実施・制約

- Supabase CLI / Docker / PostgreSQLクライアントがこの実行環境にないため、PostgreSQLによる実行テストは未実施。
- したがって、SQLの構文・依存順序・拡張機能のインストール可否・ロールの存在・ローカルSupabaseでの完全な再現性は未確認。
- `07_default_privileges.sql` は `postgres` と `supabase_admin` などのロールを参照するため、Supabase以外のPostgreSQL環境ではロールの事前確認が必要。
- Auth/StorageなどSupabase管理スキーマ、データ、ユーザー、Vault、cron定義、シークレット、プラットフォーム設定はこのスナップショットの対象外。
- このスナップショットは復旧資料であり、既存の `supabase/migrations` に混ぜたり、本番DBへ適用したりしない。

## 次の安全な検証手順

1. Supabase CLIとDocker互換ランタイムを用意する。
2. 本番プロジェクトとは別のローカル環境を起動する。
3. 依存関係を確認しながらスナップショットを順番に適用する。
4. `db reset` で空のローカルDBから再構築できるか確認する。
5. テーブル、制約、インデックス、RLS、ポリシー、関数、トリガー、権限を本番カタログと比較する。

本番DBのスキーマ・データ・migration historyには変更を加えていない。
