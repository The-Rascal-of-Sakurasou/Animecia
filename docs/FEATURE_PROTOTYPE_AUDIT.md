# ANIXIA 機能・原型監査

監査日: 2026-11-21  
対象: `main` ブランチのHTML / JavaScript / Supabase関連ファイル  
監査目的: 各機能について、画面の原型・処理コード・本番データ接続の有無を区別し、不足している機能の画面原型を用意する。

## 判定基準

- **原型あり**: 専用画面または画面領域と、対応する処理コードがリポジトリで確認できる。
- **原型あり・要補強**: 画面またはデータ処理の一部はあるが、必要な状態・操作・管理導線が不足している、または実機確認が未完了。
- **原型なし → 試作追加**: 既存の画面・処理では機能全体の利用イメージを確認できず、今回デモ用プロトタイプを追加した。
- **未確認**: ソースコードの存在だけでは実際の動作を確定できない。ブラウザ・Supabase実機テストが必要。

画面・関数・テーブルが存在することだけを理由に「本番機能完成」とは判定しない。

## 5. 今回の監査で確認できた未完了事項

1. 画面の存在と処理関数の存在は確認できたが、すべての機能についてPC・タブレット・スマートフォンでの実機操作を完了したわけではない。
2. GitHub Pagesのブラウザ実表示、全リンク遷移、Supabase接続、RLSのユーザー間分離は別途テストが必要。
3. 実績はデータ表示の原型がある一方、達成条件・進捗集計・重複付与防止の仕様を確定する必要がある。
4. 投票は今回の画面試作のみ。投票テーブル、期間、変更可否、集計、不正対策、管理機能は未実装。
5. レビュー通報は今回の画面試作のみ。通報テーブル、権限、審査履歴、異議申立て、モデレーション運用は未完了。
6. アニソンイントロクイズは今回の画面試作のみ。権利処理済み音源、音源配信方式、出題・採点・履歴DBは未実装。
7. アカウント・コミュニティ・メッセージなど一部ページはページ内に処理コードを持つ。共通化・多言語対応・レスポンシブ・エラー表示をページ横断で確認する必要がある。
8. 作品データ・人物・団体・ジャンル・タイトル画像の収録率は機能原型とは別のデータ品質課題として扱う。

## 7. 監査結論

ANIXIAの主要ナビゲーション機能は、既存リポジトリ内に対応する画面と処理コードの原型が概ね存在する。一方、実績の進捗表示、作品投票、レビュー通報・審査フロー、アニソンイントロクイズは原型が不足していたため、開発用の操作可能な画面試作を追加した。

この時点で言えるのは「主要機能の画面原型が揃い始めた」ということまでであり、「全機能が本番稼働する」「全画面の動作確認が完了した」という意味ではない。
