# ANIXIA v2 Legacy Audit

更新日: 2026-11-17

## 目的

旧実装をそのまま継続せず、ANIXIA v2の画面・データ・権限に合わせて段階的に置き換える。既存DBを破壊せず、古い条件や接続先が新仕様へ混入しないようにする。

## 確認できた事項

### フロントエンド

- ホームは新しい `anixia-client.js` を使用し、Supabaseプロジェクト `trvnxggqzlhqdhoyiliy` の `anime` テーブルを参照する。
- `anime-data.js` の `isPublic()` に、旧作品収録ルールが直接実装されている。
- `ranking.html` は `animecia_public_anime` と `anime_engagement_summary` を参照し、`anime_verification_status = verified` と `ANIXIAData.isPublic` で絞り込んでいる。
- 新Supabaseの `public` / `api` スキーマに、上記の旧ビュー名は確認できなかった。
- したがって、ランキングは新DB向けに再実装が必要。旧条件をそのまま使うことはしない。
- 既存ページは個別のHTML・CSS・JavaScriptを持つため、共通CSSを追加しただけでは全ページのUI・英語対応・機能整合性が完成したことにはならない。

### 新Supabase

- プロジェクト：`anixia`（東京リージョン、PostgreSQL 17）
- 主要テーブルは作成済みだが、2026-11-17の確認時点で作品・ジャンル・ユーザー関連テーブルの登録行数は0。
- `anime` は `is_published = true` の作品のみ匿名ユーザー・ログインユーザーへ公開するRLS。
- `genres` と公開レビューは読み取り可能。
- `ratings` と `favorites` は本人の行だけを管理できるRLSであり、匿名ユーザー向けの個人行読み取りポリシーはない。
- よって、公開ランキングで個人の評価・お気に入り行をそのまま集計する設計は避ける。必要な集計値だけを安全に公開する方式を別途設計する。

## 次の実装前に解決すること

1. 作品収録条件を白紙から決定し、取得・審査・公開の状態を分離する。
2. Annict等のデータ取得元と新DBの項目対応を確認する。
3. ホーム・検索・詳細・ランキング・季節・診断・クイズ・ライブラリを新DBへ統一する。
4. 各ページに共通ヘッダー、フッター、言語切替を導入する。
5. 日本語・英語の翻訳漏れ、空状態、エラー状態、スマートフォン表示をページ単位で検証する。
6. 集計ビュー／Edge Functionを設計する場合は、RLSと権限境界を先にレビューする。

## 変更していないもの

- Supabaseのテーブル、RLS、認証設定、既存ユーザーデータ
- 作品データの削除・一括公開・一括非公開
- 旧収録条件を用いた自動再判定

これらは新しい作品条件と移行計画が決まるまで変更しない。
