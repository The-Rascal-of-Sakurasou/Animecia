## 2. Wikidata

公式データアクセス方針：
- データ利用：https://www.wikidata.org/wiki/Wikidata:Reuse
- データアクセス：https://www.wikidata.org/wiki/Wikidata:Data_access/ja
- SPARQL Query Service：https://query.wikidata.org/

確認できた条件：
- Wikidataの構造化データはCC0で提供される。
- 出典表示は必須ではないが、Wikidataをデータの出所として記載することが推奨されている。
- APIやクエリサービスには安定性・負荷上の制約がある。User-Agentを設定し、リクエストを過剰に送らず、HTTP 429では停止して再試行を待つ。
- Wikidata項目ページにある通常の文章や画像ファイルは、構造化データと同じ条件とは限らない。ANIXIAは今回、構造化された作品名・別名・日付・話数・識別子等だけを扱い、画像・ポスター・バナー・あらすじ本文を取り込まない。
- 各作品ページにWikidataの出典リンクを表示し、サイトの「データ出典」ページでも出典を明記する。

## 3. Annict APIの条件

公式規約は2026-10-25制定、2026-11-25施行予定。

公式規約： https://annict.com/terms/api  
REST API作品情報： https://developers.annict.com/docs/rest-api/v1/works  
レート制限ヘルプ： https://wikino.app/s/annict/pages/419

確認できた条件：
- API利用料金は無料。規約を守る限り、広告・アフィリエイト等を含む商用利用も可能。
- 作品情報は、アプリケーションの提供に必要な範囲で保存・キャッシュでき、保存期間・件数に上限はない。
- 取得データを、第三者がまとめて取り出せるデータセット・ファイル・独自APIとして再配布してはならない。
- Webアプリケーションでは、開発者側で検索し、画面表示に必要な分だけを返す形が求められる。
- Annict APIの作品画像は権利者の著作物であり、Annictは画像利用を許諾する立場にない。ANIXIAの同期処理では画像URLを取得・保存しない。
- Annictの利用者情報は、作品情報とは別の条件で扱う。ANIXIAの共用トークンでは作品情報だけを取得し、ユーザー情報は取得しない。
- Annictの名称・ロゴは出典表示に利用できるが、公式・提携サービスと誤認させる表示は禁止。

現時点では新規規約の施行前であり、ANIXIAのAnnictソースは `pending` / 無効のままにする。施行日以降に改めて規約を読み、権利確認後に有効化する。

## 4. レート制限と同期方法

Annictの大量取得時は、最新の公式条件を再確認した上で、逐次取得・ページ分割・429待機を行う。現行同期機能は1回最大5ページ（最大250作品）、逐次リクエスト、ページ間隔約1.1秒、429の `Retry-After` 対応。画像フィールドは取得せず、新規作品は非公開で保存する。

Wikidataはクエリサービスの負荷を避けるため、将来の自動同期を実装する場合も少量ページ・逐次取得・キャッシュ・429時の停止を必須とする。大量の全件取得を短時間に行わない。

## 5. 公開前の人手確認

外部データに作品情報があることだけでは、ANIXIAの収録基準を満たすとは判断しない。管理者が次を確認する。

1. ANIXIAの対象である日本のアニメ作品か。
2. 対象の形式（TV・映画・OVA・ONA・SPECIAL等）に該当するか。
3. ANIXIAの方針で除外する成人向け作品ではないか。
4. 作品名・公開年・形式・公式サイト等の情報が正確か。
5. 表示する画像・説明文など、追加素材に適切な利用根拠があるか。

今回の9件は、基本タイトル・放送開始日・話数等を個別に照合した初期登録である。追加データの一括取り込みでは、原則として非公開候補に保存し、管理者が確認してから公開する。
