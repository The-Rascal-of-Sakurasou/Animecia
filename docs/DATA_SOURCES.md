# ANIXIA データソース方針

確認日：2026-11-17

## 1. 採用方針

| ソース | 用途 | 状態 |
|---|---|---|
| Annict REST API v1 | 作品の基本情報・Annict ID・放送時期・話数等 | 第一候補。規約条件を守って段階導入 |
| Jikan | 追加情報の候補 | 未採用。利用条件・再配布・商用条件の確認が完了するまで取得しない |
| TMDB | 将来の補助候補 | 未採用。商用利用条件・画像条件の個別確認が必要 |
| AniList | なし | ANIXIAのデータ取得・同期には採用しない |

## 2. Annict APIの条件

公式API利用規約は2026-10-25制定、2026-11-25施行。

公式規約： https://annict.com/terms/api  
REST API作品情報： https://developers.annict.com/docs/rest-api/v1/works  
レート制限ヘルプ： https://wikino.app/s/annict/pages/419

確認できた条件：

- API利用料金は無料。規約を守る限り、広告・アフィリエイト等を含む商用利用も可能。
- 作品情報は、アプリケーションの提供に必要な範囲で保存・キャッシュでき、保存期間・件数に上限はない。
- 取得データを、第三者がまとめて取り出せるデータセット・ファイル・独自APIとして再配布してはならない。
- Webアプリケーションでは、開発者側で検索し、画面表示に必要な分だけを返す形が求められる。
- Annict APIの作品画像は権利者の著作物であり、Annictは画像利用を許諾する立場にない。画像の再配布・改変・データセット提供は禁止。ANIXIAの同期処理では画像URLを取得・保存しない。
- Annictの利用者情報は、作品情報とは別の条件で扱う。ANIXIAの共用トークンでは作品情報だけを取得し、ユーザー情報は取得しない。
- Annictの名称・ロゴは出典表示に利用できるが、公式・提携サービスと誤認させる表示は禁止。

## 3. レート制限と同期方法

2026-11-17に確認したAnnict開発者向けヘルプでは、アクセストークンありのAPI上限は1分あたり600リクエスト（トークンと接続元IPの組）。上限は変更される可能性があるため、同期前に最新情報を再確認する。

Annictが大量取得時に求めていること：

- リクエストを並列にしない。
- 1件ずつ順番に送る。
- 1リクエスト最大50件を使う。
- 数時間〜数日に分けて取得する。
- HTTP 429では `Retry-After` を待ってから再開する。
- `RateLimit-Remaining` と `RateLimit-Reset` を確認する。

ANIXIA側の実装：

- Supabase Edge Function `sync-annict-catalog` からサーバー側で取得。
- `ANNICT_ACCESS_TOKEN` はSupabase Edge Function Secretsだけに保存。ブラウザ・GitHubリポジトリへ置かない。
- 1回の管理者実行は最大5ページ（最大250作品）。
- 逐次リクエスト、ページ間隔約1.1秒、429の `Retry-After` 対応。
- APIの `fields` を指定し、画像フィールドを取得しない。
- 同期した作品はDB既定値の `is_published=false` のまま保存する。既存の公開判断は再同期で上書きしない。

## 4. 公開前の人手確認

Annictの作品情報が存在することだけでは、ANIXIAの収録基準を満たすとは判断しない。管理者が次を確認してから公開する。

1. ANIXIAの対象である日本のアニメ作品か。
2. 対象の形式（TV・映画・OVA・ONA・SPECIAL等）に該当するか。
3. ANIXIAの方針で除外する成人向け作品ではないか。
4. 作品名・公開年・形式・公式サイト等の情報が正確か。
5. 表示する画像・説明文など、Annict API以外の情報に適切な利用根拠があるか。

確認できない作品は非公開のまま保留する。
